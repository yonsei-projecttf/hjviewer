# HJViewer 중계기(hjv-relay) 설치: Synology NAS (DSM 7.2)

앱에서 꺼진 PC의 **켜기**를 누르면 서버가 같은 네트워크에 있는 늘 켜진 NAS에 켜기 명령을 보내고, NAS가 그 PC에 매직 패킷(Wake-on-LAN)을 보냅니다. 서버나 휴대폰이 보낸 패킷은 꺼진 PC의 네트워크까지 가지 못하므로, 같은 네트워크의 기기가 대신 보내야 합니다. 이 문서는 그 일을 하는 프로그램 **hjv-relay**를 Synology NAS에 설치하는 방법입니다. 설치는 DSM 화면에서만 합니다. SSH는 필요 없습니다.

## 0. 이 프로그램이 하는 일

- **나가는 HTTPS(443)만 씁니다.** NAS에서 여는 포트가 없고, 공유기·방화벽 설정도 바꾸지 않습니다. hjv-relay가 서버에 먼저 연결해 명령을 기다립니다.
- **서버가 서명한 켜기 명령만 실행합니다.** 명령마다 서버의 서명, 받는 중계기, 만료 시각(60초), 처음 보는 명령인지를 확인합니다. 패킷은 NAS 자신의 랜카드 브로드캐스트로, UDP 포트 9와 7로만 보냅니다. 1분에 명령 10개, 패킷 120개까지만 받습니다.
- **root로 시작하지만 바로 권한을 낮춥니다.** 부트업 작업이 root로 실행하면, 자기 키를 읽은 직후 일반 사용자(uid/gid 65534, nobody)로 바뀝니다. 그 뒤로는 root 권한을 다시 얻을 수 없습니다.
- **저장하는 것**: 중계기 키 하나(`/volume1/@hjv-relay`, root만 읽기)와 로그(`hjv-relay` 공유 폴더의 `hjv-relay.log`). PC 비밀번호, 계정 정보, 토큰은 저장하지 않습니다. 로그의 MAC 주소는 끝 2바이트만 보입니다.
- **자동 업데이트는 하지 않습니다.** 새 버전은 9장처럼 직접 바꿉니다.
- 프로그램은 파일 하나(`hjv-relay`, 정적 링크, 약 2MB)입니다. 추가 패키지는 필요 없습니다.

## 1. 준비

- **x86_64 CPU를 쓰는 NAS**: DS923+, DS723+, DS423+, DS224+ 같은 Plus 모델입니다. CPU 종류는 Synology 지식 센터의 "What kind of CPU does my NAS have" 표에서 확인합니다. ARM 모델용은 아직 만들지 않았습니다.
- **DSM 관리자 계정**
- **설치 파일** `hjviewer-relay-<버전>-linux-x86_64.tar.gz`와 `SHA256SUMS`
  - 서버 주소가 들어간 빌드라 공개 저장소의 Release에는 올리지 않습니다. 비공개 빌드 저장소의 Release에서 받거나, 서버 관리자에게 받습니다.
- **승인해 줄 서버 관리자**: 6장의 등록 코드를 승인합니다.
- 볼륨이 `/volume1`이 아니면 아래 경로의 `/volume1`을 실제 볼륨으로 바꿉니다(예: `/volume2`).

## 2. 공유 폴더 만들기 (관리자만 쓰는 폴더)

hjv-relay는 부팅할 때 root로 실행됩니다. 그래서 프로그램 파일을 **관리자만 바꿀 수 있는 폴더**에 두어야 합니다. 다른 사람이 쓸 수 있는 부서 공유 폴더에 두면, 그 사람이 파일을 바꿔 root 권한으로 실행시킬 수 있습니다.

1. **제어판 → 공유 폴더 → 생성**을 누릅니다.
2. 이름은 `hjv-relay`로 합니다.
   - **네트워크 환경에서 이 공유 폴더 숨기기**(Hide this shared folder in "My Network Places")를 켭니다.
   - **휴지통 활성화**는 끕니다.
3. 암호화는 하지 않습니다. 암호화한 공유 폴더는 부팅 때 자동으로 열리지 않아 중계기가 시작되지 않을 수 있습니다.
4. 사용자 권한은 **본인(관리자)만 읽기/쓰기**로 둡니다. 다른 사용자와 그룹은 **액세스 없음**으로 둡니다.

**이 폴더에 쓸 수 있으면 NAS의 root 권한을 가진 것과 같습니다.** 감시 루프(4장)가 이 폴더의 `hjv-relay`를 root로 실행하고, 파일이 바뀌면 1분쯤 뒤에 새 파일을 실행하기 때문입니다. 그래서 다음을 지킵니다.
- 쓰기 권한은 관리자에게만 줍니다(위 4번).
- 이 폴더를 Synology Drive, Cloud Sync, ShareSync 같은 동기화의 대상으로 쓰지 않고, 백업을 이 폴더에 복원하지 않습니다.
- 이 폴더에 공유 링크나 파일 요청을 만들지 않습니다.
- PC에서 이 폴더를 네트워크 드라이브(SMB)로 연결해 두지 않습니다. 파일은 File Station으로 올립니다.

## 3. 파일 확인과 업로드

1. Windows PC에서 받은 두 파일이 있는 폴더를 열고, 주소창에 `cmd`를 입력해 명령 프롬프트를 엽니다.
2. 체크섬을 확인합니다.
   ```
   certutil -hashfile hjviewer-relay-1.6.0-linux-x86_64.tar.gz SHA256
   ```
   출력된 64자리 값이 `SHA256SUMS`의 같은 파일 이름 줄과 같아야 합니다. 다르면 설치하지 말고 다시 받습니다.
3. 압축을 풉니다. Windows 10 이상에는 `tar`가 들어 있습니다.
   ```
   tar -xzf hjviewer-relay-1.6.0-linux-x86_64.tar.gz
   ```
   `hjviewer-relay-1.6.0-linux-x86_64` 폴더에 `hjv-relay`, 이 안내서(`README-DSM.md`), 라이선스 파일이 생깁니다.
4. **File Station**에서 `hjv-relay` 공유 폴더를 열고 `hjv-relay` 파일을 업로드합니다. 경로는 `/volume1/hjv-relay/hjv-relay`가 됩니다.

## 4. 작업 스케줄러에 부트업 작업 만들기

NAS가 켜질 때마다 hjv-relay를 시작하는 작업입니다.

1. **제어판 → 작업 스케줄러 → 생성 → 트리거된 작업 → 사용자 정의 스크립트**를 고릅니다.
2. **일반** 탭을 채웁니다.
   - 작업: `HJViewer relay`
   - 사용자: `root`
   - 이벤트: **부트업**(Boot-up)
   - **활성화됨**을 켭니다.
3. **작업 설정** 탭의 **실행 명령 → 사용자 정의 스크립트**에 아래 내용을 그대로 붙여 넣습니다.

```sh
D=/volume1/hjv-relay; S=/volume1/@hjv-relay; L=$D/hjv-relay.log
[ -f "$L" ] && [ "$(wc -c < "$L")" -gt 1048576 ] && mv -f "$L" "$L.1"
nohup sh -c '
  w=
  while :; do
    if [ -x "'"$D"'/hjv-relay" ]; then
      w=
      "'"$D"'/hjv-relay" run --state "'"$S"'" >> "'"$L"'" 2>&1; rc=$?
      case $rc in 2|75|78) exit 0 ;; esac
    elif [ -e "'"$D"'/hjv-relay" ] && [ -z "$w" ]; then
      w=1
      echo "$(date "+%Y-%m-%d %H:%M:%S %z") hjv-relay 파일에 실행 권한이 없어 기다립니다." >> "'"$L"'"
    fi
    sleep 30
  done' > /dev/null 2>&1 < /dev/null &
```

이 스크립트가 하는 일:
- 스크립트 자체는 감시 루프 하나를 백그라운드로 띄우고 바로 끝납니다.
- 루프는 hjv-relay를 실행하고, 프로그램이 끝나면 30초 뒤 다시 실행합니다. 업데이트와 오류가 여기에 해당합니다.
- 볼륨이나 `hjv-relay` 공유 폴더가 아직 없으면(암호화된 볼륨이 잠금 해제를 기다리는 경우 등) 파일이 나타날 때까지 30초마다 확인합니다.
- 파일은 있는데 실행 권한이 없으면 로그에 한 번 적고 기다립니다(11장).
- 종료 코드 2(명령줄 오류), 75(같은 중계기가 이미 실행 중), 78(설정 오류)이면 루프를 끝냅니다.
- 로그는 hjv-relay를 실행할 때마다 `hjv-relay.log`에 이어 씁니다. 부팅할 때 1MB가 넘었으면 `hjv-relay.log.1`로 한 번 돌립니다. hjv-relay는 로그 파일이 2MB를 넘으면 그 뒤로는 적지 않습니다.
- 상태 폴더 `/volume1/@hjv-relay`는 hjv-relay가 처음 실행될 때 root만 쓰는 폴더(0700)로 만듭니다. `@`로 시작하는 폴더는 File Station에 보이지 않습니다.

## 5. 바로 시작하기

작업 목록에서 `HJViewer relay`를 선택하고 **실행**을 누릅니다. 재부팅할 필요는 없습니다.

**실행**을 한 번 더 눌러도 괜찮습니다. 두 번째로 시작한 hjv-relay는 로그에 "이미 다른 hjv-relay가 이 상태 폴더로 실행 중이라 끝냅니다." 한 줄을 남기고 끝나고, 그 감시 루프도 끝납니다. 다만 **실행**은 스크립트 첫 줄의 로그 돌리기도 다시 합니다. 그때 로그가 1MB를 넘었으면, 이미 실행 중인 hjv-relay는 다음에 다시 시작할 때까지 `hjv-relay.log.1`에 이어 씁니다.

## 6. 등록 코드 확인과 승인

1. File Station에서 `hjv-relay/hjv-relay.log`를 PC로 내려받아 메모장으로 엽니다. 처음 실행하면 다음과 같은 줄이 있습니다.
   ```
   2026-10-12 17:31:27 +0900 hjv-relay 1.6.0 시작 (서버 rd.example.com, 상태 폴더 /volume1/@hjv-relay)
   2026-10-12 17:31:27 +0900 권한을 uid 65534 gid 65534로 낮췄습니다.
   2026-10-12 17:31:27 +0900 중계기 ID r-kzdvvj2umnduyauf, 등록 코드 KZDV-VJ2U-MNDU-YAUF, 새 키 (DSM 7.2.1-69057 Update 5, 커널 …)
   2026-10-12 17:31:28 +0900 등록 승인을 기다립니다. 등록 코드: KZDV-VJ2U-MNDU-YAUF (서버 관리자가 이 코드로 승인합니다)
   ```
   - 위 두 줄의 등록 코드가 같은지 확인합니다. 등록 코드는 8장의 `status`로도 볼 수 있습니다.
2. **등록 코드**(`XXXX-XXXX-XXXX-XXXX`, 16자)를 서버 관리자에게 알립니다. 이 NAS로 켤 PC 하나의 HJViewer ID도 함께 알립니다. 관리자는 승인하기 전에 그 PC의 주인인 본인에게 직접(대면, 전화 등) 확인하고, 중계기가 보고한 네트워크가 그 PC의 네트워크와 맞는지 봅니다. 그런 다음 그 PC의 주인 계정에 중계기를 묶어 승인합니다.
   ```
   hjv-api admin relay approve KZDV-VJ2U-MNDU-YAUF --owner-of <PC ID>
   ```
   - 승인되면 1분 안에 로그에 `등록이 승인되어 켜기 명령을 기다립니다.`가 찍힙니다.
   - 24시간 안에 승인하지 않으면 서버의 대기 항목이 지워집니다. 중계기가 다시 요청하므로, 같은 코드로 다시 승인하면 됩니다.
   - 서버가 대기 항목을 받지 못하는 경우(로그에 `HTTP 429`가 이어지는 경우 등)에도, 관리자가 같은 명령으로 코드를 미리 승인해 둘 수 있습니다. 중계기가 다음에 연결할 때 바로 승인됩니다.
   - 등록 코드는 중계기 키에서 나옵니다. 상태 폴더(`/volume1/@hjv-relay`)를 지우지 않는 한 재부팅이나 업데이트를 해도 바뀌지 않습니다.
3. 그 뒤로 로그에는 켜기 명령이 왔을 때, 상태가 바뀌었을 때, 문제가 있을 때만 줄이 생깁니다. 평소에는 디스크에 쓰지 않으므로 디스크 최대 절전을 깨우지 않습니다.
4. 마지막으로 앱에서 꺼진 PC의 **켜기**를 눌러 확인합니다. 로그에 다음과 같은 줄이 생깁니다.
   ```
   … 켜기 3f2a9c1e (**:**:**:**:53:01, 망 10.1.4.0/22 exact): eth0 10.1.5.20/22 -> 255.255.255.255, 10.1.7.255 포트 9,7 ×3: 12/12개 보냄
   ```

## 7. 현장 시험 (서버 없이): `test-wake`

PC가 절전, 최대 절전, 종료 상태에서 NAS가 보낸 매직 패킷으로 켜지는지 서버 없이 확인합니다. 등록 전에도 할 수 있습니다.

1. **PC의 유선 MAC 주소**를 확인합니다. PC의 명령 프롬프트에서 `getmac /v`를 실행하고, "이더넷"(유선 랜카드) 줄의 물리적 주소를 적습니다. `AA-BB-CC-DD-EE-FF` 형식을 그대로 써도 됩니다.
2. **제어판 → 작업 스케줄러 → 생성 → 예약된 작업 → 사용자 정의 스크립트**를 만듭니다.
   - 일반: 작업 `HJViewer wake test`, 사용자 `root`(또는 본인 관리자 계정)
   - 일정: 시험하는 날, **5분마다** 반복
   - 사용자 정의 스크립트(MAC은 1번에서 적은 값):
     ```
     /volume1/hjv-relay/hjv-relay test-wake AA-BB-CC-DD-EE-FF --count 3 >> /volume1/hjv-relay/test.log 2>&1
     ```
   - `--net`을 주지 않으면 NAS의 모든 LAN 랜카드(컨테이너·VPN용 가상 랜카드는 빼고)로 보냅니다.
   - PC의 네트워크를 알면 `--net 10.1.4.0/22`처럼 주어 그 네트워크의 랜카드로만 보낼 수 있습니다. PC의 IP와 접두사(`10.1.7.33/22`)를 그대로 써도 됩니다.
3. PC를 다음 순서로 둡니다. 상태마다 5분 넘게 기다리며 켜지는지와 시각을 적습니다.
   1. 절전: 시작 → 전원 → 절전
   2. 최대 절전: `shutdown /h`
   3. 종료: `shutdown /s /t 0`
   4. 전원 플러그를 30초 뺐다가 다시 꽂은 뒤의 종료 상태
4. `hjv-relay/test.log`에서 보낸 시각과 랜카드를 확인합니다. 줄은 다음과 같습니다.
   ```
   2026-10-12 17:00:00 +0900 test-wake **:**:**:**:ee:ff: eth0 10.1.5.20/22 -> 255.255.255.255, 10.1.7.255 포트 9,7 ×3: 12/12개 보냄
   ```
   - `10.1.5.20/22`는 NAS 랜카드의 주소와 접두사입니다. 서버 관리자에게 알리면 중계기를 고를 때 도움이 됩니다.
   - 랜카드 이름 뒤에 `(연결 없음)`이 붙으면 그 포트에 케이블이 연결되어 있지 않습니다. 보낸 패킷이 PC에 닿지 않으므로 케이블과 포트를 확인합니다.
5. 시험이 끝나면 이 작업을 끄거나 지웁니다. 한 번만 보내려면 작업을 선택하고 **실행**을 누릅니다.

절전에서는 켜지는데 종료 상태에서 안 켜지면, PC BIOS의 Wake on LAN과 ErP(대기 전력 절감) 설정을 확인해야 합니다. PC의 "빠른 시작"도 꺼져 있어야 합니다.

## 8. 상태 확인: `status`

1. **작업 스케줄러 → 설정**에서 **실행 결과 저장**(Save output results)을 켜고, 저장할 공유 폴더로 `hjv-relay`를 고릅니다.
2. **생성 → 예약된 작업 → 사용자 정의 스크립트**를 만듭니다.
   - 사용자: `root`
   - 일정: 한 번, 지난 날짜
   - 스크립트:
     ```
     /volume1/hjv-relay/hjv-relay status --state /volume1/@hjv-relay
     ```
3. 작업을 선택하고 **실행**을 누른 뒤 **작업 → 결과 보기**(View Result)에서 출력을 봅니다. 다음 정보가 나옵니다.
   - 중계기 ID와 등록 코드, 실행 중인지
   - 등록 상태(`pending` 승인 대기, `active` 사용 중, `revoked` 폐기됨), 마지막 정상 응답 시각, 최근 오류
   - 마지막 켜기 명령의 결과
   - NAS 랜카드와 각 랜카드를 켜기에 쓰는지 여부(케이블이 빠진 포트에는 `(연결 없음)`이 붙습니다)

`hjv-relay version`은 버전과 이 빌드가 연결하는 서버 이름, 명령 공개키를 보여 줍니다.

## 9. 업데이트

1. 새 `hjviewer-relay-<버전>-linux-x86_64.tar.gz`를 받아 3장처럼 체크섬을 확인하고 압축을 풉니다.
2. File Station에서 새 `hjv-relay`를 같은 폴더에 같은 이름으로 업로드하고, **덮어쓰기**를 고릅니다.
3. hjv-relay가 실행 파일이 바뀐 것을 알아채고 스스로 끝납니다. 그때 기다리던 서버 응답이 끝난 뒤(최대 35초) 알아채고, 감시 루프가 30초 뒤에 새 버전을 시작하므로 1분쯤 걸립니다. 로그에는 `실행 파일이 바뀌었습니다(…)`와 `hjv-relay <새 버전> 시작`이 찍힙니다. 키와 등록은 그대로 유지되므로 다시 승인할 필요가 없습니다.
4. "사용 중"이라 덮어쓸 수 없으면, 먼저 기존 파일의 이름을 `hjv-relay.old`로 바꾸고 새 파일을 올립니다. 새 버전이 시작되면 `hjv-relay.old`를 지웁니다.

자동 업데이트는 없습니다. 서버가 더 새 버전을 요구하면 로그에 `…보다 오래되었습니다. 새 버전으로 바꾸세요.`가 찍힙니다.

DSM을 업그레이드한 뒤(예: 7.3)에는 8장의 `status`나 앱의 켜기로 한 번 확인합니다.

## 10. 멈추기와 제거

- **잠시 멈추기**: File Station에서 `hjv-relay` 파일의 이름을 바꿉니다(예: `hjv-relay.off`).
  - hjv-relay가 1분 안에 끝납니다.
  - 감시 루프는 파일 이름이 원래대로 돌아올 때까지 root로 30초마다 확인합니다. 멈춘 동안에도 2장의 주의가 그대로 적용됩니다.
- **제거**:
  1. 작업 스케줄러에서 `HJViewer relay` 작업을 삭제합니다.
  2. `hjv-relay` 파일을 삭제하고, **바로** NAS를 재부팅합니다. 작업을 지워도 이미 돌고 있는 감시 루프는 재부팅할 때까지 root로 30초마다 그 경로를 확인하고, 그 자리에 파일이 생기면 실행합니다. 재부팅 전에는 그 폴더에 아무것도 올리지 않습니다.
  3. 서버 관리자에게 중계기 폐기를 요청합니다: `hjv-api admin relay revoke <중계기 ID>`.
  4. 키를 지우려면 사용자 `root`의 예약된 작업(한 번)으로 `rm -rf /volume1/@hjv-relay`를 실행합니다. 키를 지우면 다시 설치할 때 새 중계기로 승인받아야 합니다.
  5. 로그도 필요 없으면 `hjv-relay` 공유 폴더를 삭제합니다.

## 11. 문제 해결

| 로그 문구 | 뜻 | 할 일 |
|---|---|---|
| (로그 파일이 없거나 비어 있음) | 작업이 실행되지 않았거나, 파일이 아직 없습니다 | 4장의 작업이 사용자 `root`, 이벤트 부트업, 활성화됨인지 확인합니다. 파일이 `/volume1/hjv-relay/hjv-relay`에 있는지도 확인합니다. 5장처럼 **실행**을 누릅니다 |
| `hjv-relay 파일에 실행 권한이 없어 기다립니다.` | 올린 파일에 실행 권한이 없습니다 | 사용자 `root`의 예약된 작업(한 번, 8장처럼 만듦)으로 `chmod 755 /volume1/hjv-relay/hjv-relay`를 한 번 실행합니다. 감시 루프가 30초 안에 시작합니다 |
| `상태 폴더를 아직 쓸 수 없습니다` | 볼륨이 아직 준비되지 않았습니다 | 자동으로 다시 시도합니다 |
| `이미 다른 hjv-relay가 … 실행 중이라 끝냅니다.` | 작업을 두 번 실행했습니다 | 정상입니다. 하나는 계속 돌고 있습니다 |
| `설정 오류: …` | 사람이 확인해야 하는 문제입니다. 감시 루프가 멈춥니다 | `설정 오류: run: …`이면 4장의 스크립트를 잘못 붙여 넣은 것이니 다시 붙여 넣습니다. 그 밖에는 문구를 서버 관리자에게 보냅니다. 고친 뒤 작업을 **실행**합니다. 키 파일이 손상된 경우 새 키를 만들면 다시 승인받아야 합니다 |
| `서버와 통신하지 못했습니다: …` | NAS가 서버에 연결하지 못했습니다(DNS, 인터넷, 방화벽, TLS 검사 장비, NAS 시계 등) | 자동으로 다시 시도합니다. NAS에서 서버의 443 포트로 나갈 수 있어야 합니다. 같은 문구가 이어지면 10분에 한 줄씩 남습니다. 문구에 `NAS의 시계가 맞는지 확인하세요`가 있거나 `TLS: … certificate`가 이어지면 NAS의 시각을 확인합니다: **제어판 → 지역 옵션 → 시간**에서 NTP 서버와 동기화하도록 합니다. 인증서 검사는 NAS의 시계로 합니다 |
| `로그 파일이 2MB를 넘어 더 적지 않습니다.` | 로그가 너무 많이 쌓였습니다 | 재부팅하면 로그를 돌리고 다시 적습니다. 그 전의 로그를 서버 관리자에게 보냅니다 |
| `SO_BINDTODEVICE를 쓸 수 없어 … 주소 bind만으로 랜카드를 고릅니다.` | DSM 커널이 오래된 버전입니다 | 동작에는 문제가 없습니다 |
| `켜기 명령 …을(를) 보내지 않았습니다: no_iface` | NAS에 그 PC와 같은 네트워크의 랜카드가 없습니다 | NAS의 네트워크 설정(제어판 → 네트워크 → 네트워크 인터페이스)과 PC의 IP를 확인합니다 |
| 로그에 `…개 보냄`이 있는데 PC가 켜지지 않음 | NAS는 매직 패킷을 보냈지만 PC가 깨어나지 않았습니다 | PC 쪽 준비([wol-pc-setup.md](wol-pc-setup.md))를 확인합니다. 결과에 따라 할 일은 [부록](#결과-적기와-읽기)에 있습니다 |
| `…: rate_limited` | 1분 안에 켜기가 너무 많았습니다 | 잠시 뒤 다시 시도합니다 |
| `…: expired` | 명령이 너무 늦게 도착했습니다(60초 만료) | 잠시 뒤 다시 시도합니다. 자주 생기면 서버 관리자에게 알립니다 |
| `서버가 이 중계기를 폐기했습니다.` | 서버에서 이 중계기를 쓰지 않게 했습니다 | 서버 관리자에게 문의합니다 |
| `서버에 이 중계기의 등록이 없습니다.` | 승인 전에 대기 항목이 만료되었거나 지워졌습니다 | 자동으로 다시 요청합니다. 6장처럼 다시 승인받습니다 |

재부팅한 뒤 로그에 시작 줄이 없고 `status`에서 "실행 중: 아니요"가 나오면, 작업 스케줄러가 부트업 작업의 자식 프로세스를 끝낸 것일 수 있습니다. 그 결과를 서버 관리자에게 알리면 Container Manager로 실행하는 방법으로 바꿉니다.

## 12. 참고

- hjv-relay는 HJViewer의 일부이며 GNU AGPL v3 라이선스입니다. 소스 위치는 함께 받은 `SOURCE.txt`에 있고, 사용한 라이브러리의 라이선스는 `THIRD_PARTY_NOTICES.txt`에 있습니다.
- 서버와 주고받는 내용은 저장소의 `relay/PROTOCOL.md`에 정의되어 있습니다.
- 명령줄 사용법은 `hjv-relay help`로 볼 수 있습니다.

## 부록. 현장 시험 보충

"현장 시험 (서버 없이): `test-wake`" 장을 보충합니다. 그 시험을 hjv-relay 없이 하는 방법과, 결과를 적고 읽는 방법입니다. PC 쪽 준비(랜카드 설정, BIOS의 Wake on LAN과 ErP, 빠른 시작, 어떤 상태로 둘지)는 [wol-pc-setup.md](wol-pc-setup.md)에 있습니다.

### hjv-relay 없이 시험하기 (DSM 내장 명령)

hjv-relay 묶음을 받기 전에도 같은 시험을 할 수 있습니다. DSM에 들어 있는 `synonet --wake` 명령이 매직 패킷을 보냅니다. 이 명령은 root 권한이 필요하고, DSM 안의 도구라 DSM 판에 따라 달라질 수 있습니다. 이 작업은 공유 폴더의 파일을 실행하지 않고 공유 폴더에 쓰지도 않습니다.

1. 현장 시험 장의 1번처럼 PC의 유선 MAC 주소를 적습니다.
2. **제어판 → 작업 스케줄러 → 생성 → 예약된 작업 → 사용자 정의 스크립트**를 만듭니다.
   - 일반: 작업 `HJViewer wol`, 사용자 `root`
   - 일정: **한 번, 지난 날짜**. 저절로 돌지 않고, 작업을 선택해 **실행**을 누를 때만 돕니다.
   - 사용자 정의 스크립트: 첫 줄의 값을 1번의 MAC 주소로 바꿉니다. `-`로 적어도 되고, 대소문자는 상관없습니다.
     ```sh
     M=00-00-5E-00-53-01
     M=$(echo "$M" | tr 'a-f-' 'A-F:')
     PATH=$PATH:/usr/syno/sbin:/usr/syno/bin
     for r in 1 2 3; do
       for i in eth0 eth1 eth2 eth3 bond0 ovs_eth0 ovs_eth1 ovs_bond0; do
         [ -e "/sys/class/net/$i" ] && synonet --wake "$M" "$i"
       done
       sleep 1
     done
     ```
   - NAS에 있는 랜 포트마다 1초 간격으로 세 번 보냅니다. 랜 포트 이름(eth0 등)을 몰라도 됩니다.
3. 이 PC에서 도는 작업이 없을 때 합니다. 절전은 그 작업을 멈추고 종료는 끝냅니다. 현장 시험 장의 순서(절전 → 최대 절전 → 종료 → 플러그를 뺐다 꽂은 뒤의 종료)로 PC를 두고, 상태마다 5분 넘게 기다린 뒤 이 작업을 선택하고 **실행**을 누릅니다. 1분 안에 켜지는지 봅니다.
   - PC가 잠들어 있으므로 DSM은 다른 기기(휴대폰의 브라우저, 다른 PC)에서 엽니다.
   - 다른 기기가 없으면 시험하는 동안 일정을 **5분마다**로 바꾸고 켜진 시각만 적습니다. 이때는 PC가 다시 잠들어도 5분 안에 다시 깨우므로 '다시 잠들기까지'는 재지 않습니다.
4. 이 작업은 보낸 기록을 남기지 않습니다. **실행**을 누른 시각을 보낸 시각으로 적습니다.
5. 시험이 끝나면 이 작업을 지웁니다.

### 결과 적기와 읽기

상태마다 한 줄씩 적습니다. 주소와 MAC 주소는 적지 않습니다.

| 상태 | 켜짐 | 걸린 시간 | 다시 잠들기까지 | 비고 |
|---|---|---|---|---|
| 절전 | | | | |
| 최대 절전 | | | | |
| 종료 | | | | |
| 플러그를 뺐다 꽂은 뒤의 종료 | | | 재지 않음 | |

- 걸린 시간: 신호를 보낸 때부터 PC가 켜질 때까지입니다. 신호를 보낸 뒤 1분 안에 켜지지 않으면 "안 켜짐"으로 적습니다.
- 다시 잠들기까지: 켜진 뒤 아무것도 누르지 않았을 때 다시 잠들 때까지입니다. 30분까지 보고, 그때까지 깨어 있으면 "30분 넘음"으로 적습니다.
- 비고: NAS가 보낸 랜카드(hjv-relay로 시험했으면 `test.log`의 랜카드 이름), 앱에서 PC가 켜짐으로 보이기까지 걸린 시간.

| 결과 | 뜻과 할 일 |
|---|---|
| 절전에서도 켜지지 않음 | 신호가 PC에 닿지 않았거나 랜카드가 깨우기를 하지 않습니다. 먼저 PC의 랜카드 설정([wol-pc-setup.md](wol-pc-setup.md) 3장)을 봅니다. 그래도 안 되면 NAS와 PC가 같은 네트워크(같은 스위치와 VLAN)인지, 학내망에 포트 보안(802.1X 인증, 포트 격리, 브로드캐스트 제한)이 있는지 네트워크 담당에게 묻습니다 |
| 절전은 되고 최대 절전이나 종료는 안 됨 | 꺼진 동안 랜카드에 전원이 없거나, 종료할 때 Windows가 깨우기를 껐습니다. [wol-pc-setup.md](wol-pc-setup.md)의 4장(BIOS)과 5장(빠른 시작)을 확인하고 그 상태만 다시 시험합니다 |
| 플러그를 뺐다 꽂은 뒤의 종료만 안 됨 | 전원이 다시 들어온 뒤 한 번 켜졌다 꺼져야 깨우기를 준비하는 PC입니다. 정전 뒤에는 PC를 한 번 켜 둡니다([wol-pc-setup.md](wol-pc-setup.md) 4장의 AC 전원 복구) |
| 켜졌다가 몇 분 안에 다시 잠듦 | 사람 없이 깨어난 Windows의 무인 절전입니다. HJViewer 1.6.0에 로그인한 PC는 깨어난 뒤 10분 동안 잠들지 않습니다([wol-pc-setup.md](wol-pc-setup.md) 6장) |

결과는 서버 관리자에게도 알립니다. 서버가 앱에 보이는 준비 안내를 고칠 때 씁니다. 운영자 PC의 결과는 [wol-pc-setup.md](wol-pc-setup.md#현장-시험-결과-운영자의-pc)에 있습니다.
